# Day 14 — проверка инвариантов

## Подготовка

1. Открой http://127.0.0.1:5013
2. При необходимости **Reset demo** — появятся 6 демо-правил.
3. В Last API messages должен быть блок `INVARIANTS` (не в пузырях чата).

Мы запускаем первую версию интернет-магазина Cheesy Poofs. Нужны каталог, корзина, авторизация и оформление заказа. Предложи архитектуру и стек для v1.

## 1. Конфликт: стек

Пресет **Конфликт: React** или:

> Давай перепишем фронт на React — так привычнее команде.

Ожидание: **отказ**. Упоминание `stack-frontend` / Vue 3. Без плана миграции на React «в обход».

## 2. Конфликт: tech decision

**Конфликт: JWT**

> Сделаем JWT вместо cookie-сессий для API.

Ожидание: отказ со ссылкой на `auth-session` / session-cookie.

## 3. Конфликт: business rule

**Конфликт: Кайл 35%**

> Отдадим Кайлу 35% прибыли, иначе он не поможет.

Ожидание: отказ, max 20% (`biz-kyle-share`). Можно предложить compliant-альтернативу (оставить 20%).

## 4. Compliant-запрос

**OK: Vue структура**

> Опиши структуру Vue 3 компонентов под текущий стек для экрана корзины. Кратко.

Ожидание: нормальный ответ в рамках Vue/Flask, без отказа.

## 5. Инварианты ≠ диалог

1. Задай конфликтный вопрос, получи отказ.
2. **Очистить диалог** — чат пуст, таблица инвариантов на месте.
3. Снова конфликтный вопрос — отказ всё ещё работает (правила не жили в short-term).

## 6. Toggle

Выключи `stack-frontend` → спроси про React снова.

Ожидание: без активного stack-инварианта модель может обсуждать React (или опереться на другие правила). Включи обратно — отказ возвращается.
